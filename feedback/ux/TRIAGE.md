# UX panel triage

Eight lenses, 157 findings (first-time-user, interaction, accessibility, content, visual, approver,
hostile, cli-admin). Dispositions by theme. Owners: **core** (kernel, runner, cogs, compile, release,
extract, frames, authz; the maintainer), **shell** (`hubproto/shell.py`, its tests), **cli** (`hubproto/cli.py`,
`cli_records.py`, `docker/entrypoint.sh`, README, DEV-NOTES), **policy** (seed Frames), **planned** (production
design in the plan; the prototype keeps the seam), **stale-release** (the running container pinned a release
compiled before the last fix pass; fixed by compiling and releasing again after the rebuild, and the entrypoint
now says when Frames differ from the release in force).

## Majors by theme

**Feedback and wording (shell):** a status line after every POST saying what happened (first-time-user-6, interaction-6, accessibility-11, interaction-19); approver lands on the next waiting item or the inbox, not a page headed "failed" (interaction-6, approver-13); failures reported once (first-time-user-14); "meaning of your signature" explained once per card type with examples, reject reason separate (first-time-user-5, approver-14); why-sentences as "Who may: …; you are: …; ask: …" not list reprs (content-7, first-time-user-19); record header without the unasked "Why: denied" (content-8); money as `12,000.00 USD`, dates as `6 Nov 2026`, no floats or ISO timestamps (content-10); notifications in sentences with a link (content-12, interaction-19); breadcrumbs folder → process → item (content-13); one name per thing: Approval (not Gate/checkpoint/decision/guard), Supplier bill, Policy version, Item number (content-5, content-6, first-time-user-9); history as sentences with JSON behind a disclosure (first-time-user-20, content-18, visual-13); error pages have an h1 and a specific title (accessibility-16).

**Inbox and decisions (shell):** mine versus informational versus waiting-on-others (first-time-user-12, approver-16: Overdue only when overdue, messages do not mirror cards); co-assignees shown and "decided by X" when a co-assignee decided (approver-7); duplicate hint for identical items (approver-8); the policy band and the human criterion on the card (approver-9); blocked items show why and disable Approve (approver-10); escalated cards quote the escalation sentence and the original (approver-6); goods receipt lines as a table with the over-receipt warning before the buttons (first-time-user-11); a decide section on the record page for the assignee (visual-7); search and newest-first lists (first-time-user-7); Kanban columns by meaning, actionable first (visual-15).

**Forms (shell):** pickers instead of locators and JSON (first-time-user-13, content-9, interaction-14, accessibility-13); labels on every control, formats stated, blank select options labelled (interaction-13, interaction-16, interaction-17, accessibility-6, accessibility-7); message form needs a body and defaults to a person; sender sees it sent (interaction-8); hold needs a reason (interaction-10); cancel confirms with one label (interaction-12); check-out for the author, the owner or a document controller, check-in needs a check-out, undo check-out (interaction-11); resubmit marks required fields (interaction-18); button says "File a supplier bill" (interaction-20); home as a front door: counts that link, one-line Start entries with a disclosure, role-trimmed rail (first-time-user-8, content-4, content-11, visual-12); Boards opens on the user's own work (content-14).

**Accessibility (shell):** skip link, headings per item, list semantics and `aria-current` on the rail, no auto-submit on Acting as, `scope` on tables, link text with the item name, AA contrast in both themes, 3:1 control borders, visible focus style, no fixed widths (accessibility-2, -8, -9, -10, -12, -14, -15, -17, -18; visual-8, -9, -10, -11, -16).

**Policy owner surfaces (shell + cli):** `/release/<digest>` with the sentence-level diff against the parent, each change's decisions and the proposal link; `/releases` as a list of versions (cli-admin-15, content-15); `/frame` pages read the current file and cite file lines including frontmatter (cli-admin-5, cli-admin-6, first-time-user-10: core makes citations absolute); admin page trimmed to policy owners and written as "people and roles" (content-16); conformance as a table (content-17); `proposals` verb, `--help` with verb descriptions in order of use, no tracebacks, exit codes, `--as` must be a member, dates validated, wrong root refused, backup and restore documented, noise-free change lists (cli-admin-8..14, 16..19; hostile-14, hostile-15).

**Core, this pass:** validation by field spec; reject ignores fields; retry and cancel only by the owner (or an approver), retry accepts fields; owner notified on cog decisions and auto-closures; NCR rationale no longer says "confirmed at the Gate" when a cog decided (first-time-user-15); citations absolute; FrameStore errors name the file; `why` singularises the object; notifications once per event.

**Planned:** delegation and "not me" (approver-12: plan 7.4), batch decisions (approver-13), where-used of a Frame sentence, OpenFGA/Keycloak identity (hostile-4 beyond the prototype), paging and search backed by Postgres projections, sortable file library with icons and selection (visual-14).

## Policy changes

- finance-policy: bill approvals have a 5-day SLA (present since round 1; the running release predates it: stale-release).
- document-control-sop: the doc-reviewer cog's criteria stay (a minor change may be approved within fixed criteria); the owner is now told.
